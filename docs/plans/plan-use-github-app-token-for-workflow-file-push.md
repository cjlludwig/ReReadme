# Plan: Use GitHub App Token for Workflow File Push

## Context

The publish workflow (`publish.yml`) has a step that creates a branch, patches `.github/workflows/readme-ci.yml` with the new version ref, and opens a PR. `GITHUB_TOKEN` is platform-blocked from pushing changes to `.github/workflows/` files — this cannot be fixed with `permissions:` syntax. A GitHub App token (via `actions/create-github-app-token`) is the correct modern solution.

---

## Manual Setup (user must do this in GitHub UI before YAML changes work)

### 1. Create the GitHub App
- Go to https://github.com/settings/apps/new
- **Name**: `rereadme-publish-bot` (must be globally unique)
- **Homepage URL**: `https://github.com/cjlludwig/ReReadme`
- **Webhook**: uncheck "Active"
- **Repository permissions**:
  - Contents: Read and write
  - Workflows: Read and write
  - Pull requests: Read and write
- **Where can this be installed**: Only on this account
- Click **Create GitHub App** — note the **App ID** shown on the next page

### 2. Generate a Private Key
- On the app settings page, scroll to **Private keys** → **Generate a private key**
- A `.pem` file downloads — keep it

### 3. Install the App on the Repo
- App settings → **Install App** → Install next to your account
- Select **Only select repositories** → `cjlludwig/ReReadme` → Install

### 4. Add Secrets to the Repo
Go to https://github.com/cjlludwig/ReReadme/settings/secrets/actions and add:

| Secret | Value |
|--------|-------|
| `APP_ID` | The numeric App ID from step 1 |
| `APP_PRIVATE_KEY` | Full contents of the `.pem` file (including header/footer) |

## Code Changes

**File**: `.github/workflows/publish.yml`

### 1. Remove `workflows: write` from permissions (it was invalid/non-functional)

```yaml
permissions:
  contents: write      # push tags
  id-token: write      # required for npm provenance attestation
  pull-requests: write # open PR to update readme-ci.yml version ref
```

### 2. Add token generation step (insert after "Create GitHub Release" step)

```yaml
      - name: Generate GitHub App token for workflow file push
        id: app_token
        if: steps.version_check.outputs.changed == 'true'
        uses: actions/create-github-app-token@v1
        with:
          app-id: ${{ secrets.APP_ID }}
          private-key: ${{ secrets.APP_PRIVATE_KEY }}
```

### 3. Update the final step to use the App token + reconfigure git remote

```yaml
      - name: Update readme-ci.yml to new version
        if: steps.version_check.outputs.changed == 'true'
        env:
          VERSION: ${{ steps.version_check.outputs.local }}
          GH_TOKEN: ${{ steps.app_token.outputs.token }}
        run: |
          git remote set-url origin "https://x-access-token:${GH_TOKEN}@github.com/cjlludwig/ReReadme.git"
          BRANCH="chore/update-gha-ref-v${VERSION}"
          git checkout -b "$BRANCH"
          sed -i "s|cjlludwig/ReReadme@v[0-9]*\.[0-9]*\.[0-9]*|cjlludwig/ReReadme@v${VERSION}|g" \
            .github/workflows/readme-ci.yml
          git add .github/workflows/readme-ci.yml
          git diff --cached --quiet || git commit --no-verify -m "chore: update GHA ref to v${VERSION} [skip ci]"
          git push origin "$BRANCH"
          gh pr create \
            --title "chore: update GHA ref to v${VERSION}" \
            --body "Auto-generated by publish workflow: bumps \`readme-ci.yml\` action ref to \`v${VERSION}\`." \
            --base main \
            --head "$BRANCH"
```

Key changes vs current:
- `GH_TOKEN` → `steps.app_token.outputs.token` (was `secrets.GITHUB_TOKEN`)
- Added `git remote set-url` as first line — the initial checkout baked `GITHUB_TOKEN` into the remote URL; this repoints it to the App token before the push
